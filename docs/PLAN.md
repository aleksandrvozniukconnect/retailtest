# План: інструкції зі збирання меблів за QR-кодом

Мета: зборщик сканує QR-код на упаковці й бачить на телефоні 3D-модель, кроки збирання, список деталей, фурнітуру й креслення. Дані беруться прямо з моделі в Базис-Мебельщику, без ручного набору.

## 1. Що пропонує maxbazis.com/scripts

Сайт продає й роздає скрипти для Базис-Мебельщика. Для нашої мети важливі два з них:

| Скрипт | Що робить | Нам потрібно |
|---|---|---|
| «3D просмотр» | Одна кнопка в Базисі, і модель відкривається в браузері в 3D. Є посилання для клієнта й окреме для цеху. Цеху по натисканню на деталь видно деталі, фурнітуру й отвори. Кнопки «Сборочный» і «Детальный»: схеми збирання по блоках, креслення деталей, PDF. Моделі можна зберегти в особистий кабінет. | Так, це ядро |
| «Сборочный чертеж» | Загальний вигляд, список блоків, уся фурнітура з кількістю. Лист на кожен блок: 3D з номерами деталей і специфікація. Вигляд спереду з висотами полиць від низу, щоб розмічати рулеткою. Кромка й пази в специфікації. Детальний лист на кожну деталь із присадкою за галочкою. Відкривається на сайті, PDF однією кнопкою. Креслення зберігається на сайті 1 день. Без інтернету зберігає файл поруч із моделлю. | Так |
| «Размеры», «Проверка петель», «Список деталей» | Працюють усередині Базису: розставляють розміри, перевіряють петлі, вивантажують таблицю в Excel. | Ні, це інструменти конструктора, а не зборщика |

Як влаштований сам сайт (видно з його коду `assets/auth.js`): є сервер з API (`/api/me`, `/api/hit`), акаунти (`/account/`), статистика для власника (`/admin/`), а скрипти завантажуються з `/downloads/` лише після входу. Код самих скриптів закритий за входом, ми його не беремо і не копіюємо. Робимо власну реалізацію за офіційним API Базису.

## 2. Загальна схема

```
Базис-Мебельщик                Сервер                     Телефон зборщика
┌────────────────┐  JSON   ┌──────────────────┐  посилання  ┌──────────────────┐
│ скрипт-експорт │ ──────► │ зберігає модель, │ ──────────► │ model.html:      │
│ (наш .js)      │  HTTPS  │ видає id і QR    │   QR-код    │ кроки, 3D, список│
└────────────────┘         └──────────────────┘             └──────────────────┘
```

Без інтернету скрипт зберігає JSON у файл, і його можна відкрити на сайті кнопкою «Відкрити файл моделі».

## 3. Що відомо про скрипти Базису

Джерело: офіційний репозиторій [BazisSoft/Scripts](https://github.com/BazisSoft/Scripts) (MIT) з файлом типів `node_modules/@types/bazis/index.d.ts` і розширення [vscode-bazis-debug](https://github.com/BazisSoft/vscode-bazis-debug). Офіційна довідка на `cdn.bazissoft.ru` з нашого середовища недоступна, тож її треба звірити окремо.

- **Мова й запуск.** Скрипти на JavaScript, файли `.js` лежать у `Documents\BazisX\Scripts`. Рушій вбудований (`node.dll`), Node.js ставити не потрібно. На форумі згадують новий рушій на Node.js v20 у бета-версії.
- **Обхід моделі.** Глобальний `Model`: `Count`, `Model[i]`, `Objects`, `forEach(fn)`, `forEachPanel(fn)`, `GSize`, `GMin`, `GMax`. Структурний об'єкт (блок) має `List === true`, вміст через `AsList()`.
- **Будь-який об'єкт (`Object3`).** `Name`, `ArtPos` (позиція), `Visible`, `Position`, `GSize`, `GMin`/`GMax` (у своїй системі координат), `GabMin`/`GabMax` (габарит), `ToGlobal()`/`NToGlobal()` для перерахунку координат, `UserProperty` (власні властивості), `UID`.
- **Панель (`AsPanel`).** `Contour` (2D-контур), `ContourWidth`, `ContourHeight`, `Thickness`, `MaterialName`, `TextureOrientation`, `Butts` (кромки), `Plastics` (пластик), `Cuts` (пази), `IsContourRectangle`.
- **Кромка (`Butts.Butts[i]`).** `ElemIndex` (який елемент контуру), `Material`, `Thickness`, `Width`, `Sign`. Сторону визначаємо за елементом контуру: `Contour.Objects[ElemIndex].AsLine().Pos1/Pos2`.
- **Пази (`Cuts.Cuts[i]`).** `Name`, `Sign`, `Trajectory`, `Contour`.
- **Кріплення й фурнітура.** Кріплення — блок з `IsFastener() === true`. Є `FindConnectedFasteners()` і `FindFastenedObjects()`: які деталі воно з'єднує. Окремого API «отвори» в типах немає: присадку доведеться виводити з положення кріплення відносно панелі. Це головне технічне питання, перевіряти на реальній моделі.
- **Дані замовлення.** Глобальний `Article`: `Name`, `Code`, `OrderName`, `OrderCode`, `Notes`.
- **Файли.** `system.askWriteTextFile(ext, text)`, `system.writeTextFile` (застаріле, замість нього `fs.writeFileSync`), `system.readTextFile`, `system.askFolder`.
- **Мережа й браузер.** У типах розширення є модулі Node `https`, `http`, `fs`, `child_process`. Тобто скрипт може відправити модель на сервер і відкрити посилання в браузері (`system.exec` або `child_process`). Перевірити на вашій версії Базису.
- **Вікна.** `NewForm(caption)`, властивості скрипта (`ScriptProperty`), поля вводу `NewNumberInput`, `NewMaterialInput` та інші. Знадобиться для вікна налаштувань («що вивантажувати», «посилання для клієнта чи цеху»).
- **Версії.** `system.apiVersion`. Старі скрипти можуть не працювати в нових версіях, тому перевіряємо версію на старті.

## 4. Формат даних (уже працює на сайті)

```json
{
  "id": "cabinet-01",
  "name": "Шафа Bergen 600×720×560",
  "materials": { "ЛДСП 16": "#d9c4a0" },
  "blocks": [{
    "id": "body", "name": "Корпус",
    "parts": [{
      "pos": 1, "art": "1", "name": "Бік лівий", "material": "ЛДСП 16",
      "size": [16, 720, 560], "at": [0, 0, 0], "dims": [720, 560, 16],
      "edge": ["w1"], "grooves": "Паз під ХДФ",
      "holes": [{ "l": 8, "w": 60, "d": 8, "depth": 12 }]
    }],
    "hardware": [{ "name": "Євровинт 7×50", "qty": 12 }],
    "steps": [{ "text": "…", "parts": [1, 3], "hardware": [{ "name": "Євровинт 7×50", "qty": 2 }] }]
  }]
}
```

- `size`/`at` — габарит у мм у системі координат сайту (Y — вгору).
- `dims` — довжина × ширина × товщина для специфікації.
- `edge` — сторони з кромкою: `l1`, `l2` (довгі), `w1`, `w2` (короткі).
- `steps` необов'язкові: без них сайт робить один крок на блок.

Наступне розширення формату: справжній контур панелі й поворот (зараз деталь показується як паралелепіпед за габаритом), текстури матеріалів, розміри з моделі.

## 5. Етапи

| Етап | Що робимо | Результат | Статус |
|---|---|---|---|
| 1. Перегляд | 3D, кроки збирання, список деталей, креслення, PDF, QR-наліпка | `model.html`, `qr.html` | Готово |
| 2. Скрипт-експорт | Скрипт у Базисі вивантажує модель у JSON: блоки, панелі, матеріали, кромка, пази, кріплення | `bazis-scripts/export-instruction.js` | Чернетка, потрібна перевірка в Базисі |
| 3. Сервер | Прийом моделі (`POST /api/models`), зберігання, видача за id, посилання для клієнта й цеху, автоматичний QR. Варіант: Vercel (функції + Blob-сховище) | Модель отримує посилання одразу з Базису | Далі |
| 4. Кнопка «відправити» в скрипті | Скрипт сам відправляє JSON на сервер і відкриває посилання в браузері; без інтернету зберігає файл | Одна кнопка в Базисі | Після етапу 3 |
| 5. Точність моделі | Контури й повороти панелей, присадка з кріплення, текстури | Деталі виглядають як у Базисі | Після перевірки на реальних моделях |
| 6. Кроки збирання | Редактор кроків на сайті або правила в скрипті (порядок блоків, низ → верх) | Справжня покрокова інструкція | Далі |
| 7. Кабінет | Вхід, список своїх моделей, термін зберігання, статистика переглядів | Кілька виробників/конструкторів | За потреби |

## 6. Ризики й відкриті питання

1. **Перевірка в Базисі.** Базис — програма для Windows, у нашому хмарному середовищі її немає. Кожну версію скрипта перевіряєте ви на своєму комп'ютері й надсилаєте результат (JSON або помилку).
2. **Версія API.** Типи в репозиторії BazisSoft датовані 2018 роком. Назви властивостей у вашій версії можуть відрізнятися.
3. **Отвори (присадка).** Прямого API немає. Шлях: кріплення → `FindFastenedObjects()` → положення кріплення в системі координат панелі (`ToObject`). Потрібні реальні моделі для перевірки.
4. **Осі координат.** У Базисі й на сайті осі можуть не збігатися. Перевіряється на одній тестовій моделі, далі одна константа в скрипті.
5. **Товарний знак.** «Базис-Мебельщик» — товарний знак правовласника. Пишемо «скрипт для Базис-Мебельщика», без логотипів.

## 7. Що потрібно від вас

1. Версія Базис-Мебельщика (і `system.apiVersion`, якщо вийде подивитися).
2. Одна-дві реальні моделі (файл `.b3d` не потрібен, достатньо результату запуску скрипта-експорту).
3. Рішення по серверу: Vercel (у вас підключений) або інший хостинг.
4. Хто додаватиме вироби: тільки ви чи кілька виробників (від цього залежить, чи потрібні акаунти).
